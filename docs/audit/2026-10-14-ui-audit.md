# JobRadar — UI/UX Audit

**Date:** 2026-10-14. This audit was done by reading the code, without running the app. Line numbers refer to files under `src/`. Each finding lists the plan card that fixes it, from `docs/plan/production-readiness.md`.

## 1. Information architecture → P5.6
- **There are six routes:**
  - `/`: the dashboard.
  - `/bangladesh`: almost a copy of `/` with a different prefilter.
  - `/following`.
  - `/applied`: the Favorite and Applied pipeline.
  - `/boards`: sources, plus global settings at the bottom.
  - `/api-keys`.
- **Duplicated paths and markup:**
  - Pinned countries link to `/?country=X`, while Bangladesh has its own page. These are two competing paths to the same thing.
  - `/applied` duplicates `/?status=favorite` and `/?status=applied`.
  - The hero and stat-tile markup is copy-pasted across 5 pages, each with a different pastel accent.
- **Inconsistencies:**
  - `/bangladesh` doesn't pass `followedCompanies` (`bangladesh/page.tsx:106`), so its follow stars are always empty.
  - Skill chips always link to `/?q=` (`ListingCard.tsx:43`).
  - Settings are buried at the bottom of `/boards` (`boards/page.tsx:174`).
  - `revalidateAll` skips `/bangladesh` (`actions.ts:26`).
  - "Bangladesh" is a hard-coded top-level nav item, which is a personal-tool leftover.

## 2. Design system → P5.1, P5.2
- The `@theme` in `globals.css` is minimal:
  - `ink` and `sand` are unused.
  - The `coral` scale is incomplete, but `app/page.tsx:91` uses `text-coral-300`, which doesn't exist.
  - There are no radius, shadow, type or tracking tokens.
- Arbitrary values are everywhere:
  - about 13 different `shadow-[…]` values;
  - `text-[11px]` ×38, `text-[10px]` ×7, `text-[15px]` ×8;
  - 7 different tracking values;
  - raw hex colours in the CSS.
- There's no dark mode: `color-scheme: light` is hard-coded.
- Geist is referenced, but `next/font` never loads it, so the browser falls back to the system font.
- There are no shared primitives:
  - the same button class string is repeated 20+ times;
  - `Field` exists only inside `boards/page.tsx`;
  - empty states are written 6 times.
- The global `* { border-color }` reset fights the utility classes.

## 3. Behaviour & feedback → P5.3, P5.4
- Server-action forms have no pending, success or error feedback. This covers status, follow, pin, add/toggle board, settings, tags and pipeline moves.
- Nothing is optimistic, and nothing guards against a double submit.
- `addBoardAction` returns `void`, so validation errors vanish.
- **Destructive actions:**
  - Delete board has no confirmation (`boards/page.tsx:162`), even though it deletes every listing on that board.
  - Hide and remove-from-pipeline have no undo.
  - Revoke uses `window.confirm` and has no pending state.
- **What already works well:** `RefreshButton`/`RefreshStatusBar`, `CreateKeyForm` and `TestBoardButton`.
- `loading.tsx` exists only for `/applied` and `/following`, and those skeletons don't match the real layouts.
- There is no `error.tsx`, `global-error.tsx` or `not-found.tsx`, and no toasts.
- The empty state doesn't tell "no data yet" apart from "filters too narrow".

## 4. Accessibility → P5.8
- **What's already good:** skip link, `aria-current`, the main icon buttons are labelled, `aria-expanded` on facets, the refresh progressbar, reduced-motion support.
- **Gaps:**
  - **Mobile filter dialog:** no focus trap, no Esc, no focus return, and the background isn't inert.
  - **Labels and toggle state:**
    - The pin button has only a `title`, and it's `opacity-0` until hover (`FacetSidebar.tsx:112`).
    - Toggles have no `aria-pressed`.
    - Remove-tag buttons read only as "#tag".
  - **Non-JS fallbacks:**
    - Disabled pagination links stay in the tab order.
    - The `FilterBar` search needs JS (`preventDefault`).
  - **Screen-reader support:**
    - There's no `aria-live` on test or copy results.
    - `ListingCard` has no heading, so headings navigation can't list the jobs.
  - **Contrast:** `slate-400` on white (about 2.6:1) is used 50+ times for meaningful text.
  - **Touch targets:** facet rows are about 24px tall and pin buttons about 20px.
  - **Dates:** `toLocaleString()` and `timeAgo` render on the server, which can cause hydration and staleness drift (`boards/page.tsx:141`, `api-keys/page.tsx:83`).

## 5. Responsiveness → P5.6, P5.9
- The sticky header can stack 4 rows on a phone: logo, nav, pinned and refresh.
- The mobile nav scrolls sideways with no visual cue that it scrolls.
- The desktop sidebar uses a magic `top-[8.75rem] h-[calc(100vh-10rem)]`, which breaks when the header height changes.
- `FacetSidebar` renders the full facet markup twice, once for desktop and once for mobile.

## 6. Product gaps → P3.3, P5.7, P6.2
- There's no landing page, onboarding, auth UI, settings page or account page.
- There are no OG, icon or manifest metadata, and no per-page titles (only `/api-keys` has one).
- `public/` holds only the default Next.js SVGs.
- There's no 404 or error page.

## 7. Component quality → P5.5
- `FacetSidebar.tsx` (340 lines) mixes URL state, the desktop aside and the mobile dialog. It should be split into `FacetSection`, `MobileFilterSheet` and a `useFacetParams` hook, which `FilterBar` and `Pagination` should share too.
- `ListingCard.tsx` (278 lines) has 3 copies of the badge markup. `PipelineCard` duplicates the card again. `timeAgo` belongs in `src/lib`.
- `app/page.tsx` and `bangladesh/page.tsx` repeat the whole feed shell; it should be one shared `JobFeed`.
